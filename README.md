# 🩻 AI Mentor — הנדסה ביו-רפואית

מערכת ליווי AI שבועית לתלמידי כיתה י' בקורס חקר AI באבחון תמונה רפואית.
התלמידים אינם "בונים מודל" אלא **מריצים ניסויים מבוקרים** ובודקים מה באמת
משפיע על התוצאה — ראו [מבנה הקורס](#מבנה-הקורס).

כוללת צ'אט מבוסס Gemini לכל תלמיד/ה (3 שאלות מוערכות שבועיות + עזרה חופשית
בלתי מוגבלת), פאנל ניהול למורה, ושלושה כלי בדיקה תחת `tools/` שכל ייצוא מהם
מתויק אוטומטית בתיקיית התלמיד/ה ב-Drive.

## מבנה הפרויקט

```
index.html              נקודת הכניסה
css/style.css           עיצוב קליני כהה, מותאם מובייל
js/config.js            הגדרות גלובליות (כולל כתובת ה-API)
js/api.js               שכבת תקשורת מול השרת + מצב פיתוח מקומי
js/ui.js                רכיבי ממשק משותפים (טוסט, פס עליון)
js/auth.js              מסך התחברות + חיוב החלפת סיסמה בכניסה ראשונה
js/excelImport.js       פרשור קובץ Excel של תלמידים (SheetJS) + גזירת פרטי התחברות
js/main.js              ניתוב בין מסך תלמיד/מורה
tools/evaluate/         כלי הערכת מודל: מדדים, מטריצת בלבול, מפת קשב, גרפים
tools/perturb/          כלי הפרעות: מה באמת מניע את ההחלטה
tools/notebook/         מחברת ניסוי: השערה שננעלת לפני המדידה, תנאים, מסקנה
tools/_filing.js        מודול התיוק האוטומטי (מקור, מועתק לתוך שלושת הכלים)
js/studentChat.js       הצ'אט המאוחד עם ה-AI Mentor (תמונות + 3 שאלות מוערכות + עזרה חופשית)
js/teacherDashboard.js  פאנל ניהול: ייבוא, נושא שבועי, מעקב ציונים, תמלולים, ייצוא
backend/Code.gs         קוד השרת ל-Google Apps Script (Sheets + Gemini)
```

## הרצה מקומית מיידית (ללא שרת)

כולל **מצב פיתוח מקומי** שמדמה את רוב ה-API באמצעות `localStorage`. שיחת
ה-AI Mentor עצמה מוצגת במצב פיתוח כתסריט מדומה קבוע (לא AI אמיתי) — טוב
לבדיקת הממשק, לא לבדיקת איכות השאלות בפועל. יש להריץ משרת HTTP מקומי (לא
לפתוח את `index.html` ישירות כקובץ, כי הדפדפן חוסם ES Modules ב-`file://`):

```bash
py -m http.server 8000
```

ואז לפתוח `http://localhost:8000`.

משתמשי ברירת מחדל במצב הפיתוח:
- **מורה/ניהול:** `admin` / `admin123`
- **תלמידה לדוגמה:** `מיכל5678` / `140810`

## חיבור לשרת אמיתי (Google Apps Script + Sheets + Gemini)

1. פתחו [sheets.google.com](https://sheets.google.com) וצרו גיליון **חדש וריק**
   (למשל "AI Mentor - נתונים").
   > ⚠️ **חובה גיליון ייעודי.** אל תחברו את הסקריפט לגיליון של מערכת אחרת.
   > אם כבר קיים שם גיליון בשם `Users`, הנתונים ייכתבו לתוכו בהזזת עמודות —
   > המערכת תזהה זאת ותיכשל עם הודעה מפורשת, אבל עדיף פשוט להתחיל מגיליון ריק.
2. בתפריט **הרחבות ← Apps Script** יפתח עורך הסקריפטים המחובר לגיליון.
3. מחקו את התוכן שבקובץ `Code.gs` שנפתח כברירת מחדל, והדביקו במקומו את התוכן
   המלא של [`backend/Code.gs`](backend/Code.gs) מתוך הפרויקט הזה.
4. **הגדירו את מפתח ה-Gemini** — ראו [הוראות מפורטות בהמשך](#הוספת-מפתח-gemini-שלב-מפורט).
5. לחצו **פריסה (Deploy) ← פריסה חדשה (New deployment)**.
   - סוג: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (כדי שהאפליקציה תוכל לקרוא לשרת ללא התחברות Google)
6. אשרו הרשאות (כולל גישה ל-Drive וליצירת מסמכי Docs — נדרש ליומני התלמידים
   ולייצוא), ואז העתיקו את כתובת ה-**Web app URL** שמתקבלת (מסתיימת ב-`/exec`).
7. הדביקו את הכתובת בשדה `API_URL` בקובץ [`js/config.js`](js/config.js).
8. **הפעילו את הייצוא השבועי האוטומטי**: בעורך ה-Apps Script, בתפריט הפונקציות
   בראש המסך בחרו `installWeeklyTrigger` ולחצו ▶ Run פעם אחת (מריץ Trigger
   קבוע לכל יום ראשון ב-20:00 — ניתן לשנות בקוד אם רוצים יום/שעה אחרים).
9. בפעם הראשונה שקוראים לשרת, הוא ייצור אוטומטית את הגיליונות הדרושים
   (`Users`, `WeeklyTopics`, `WeeklyCheckIns`, `HelpChatLog`, `Sessions`,
   `Usage`, `Artifacts`) עם
   משתמש מורה ברירת מחדל (`admin`/`admin123`). **החליפו אותה מיד** בפאנל
   הניהול, בכרטיס "סיסמת המורה" — היא מתועדת כאן ולכן ציבורית.
10. פרסמו את התיקייה (index.html + css/ + js/) לכל אירוח סטטי (GitHub Pages,
    Google Sites, שרת בית הספר).

### הוספת מפתח Gemini (שלב מפורט)

המפתח **אינו נשמר בקוד ואינו נכנס ל-git** — הוא נשמר בהגדרות פרויקט ה-Apps
Script, ו-`Code.gs` קורא אותו בזמן ריצה דרך
`PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY')`.

**יצירת המפתח:**
1. היכנסו ל-[aistudio.google.com/apikey](https://aistudio.google.com/apikey).
2. לחצו **Create API key** והעתיקו אותו.
3. גוגל מנפיקה מפתחות ביותר מפורמט אחד (`AIza...`, `AQ.A...` ואחרים). **אל
   תסיקו מהקידומת שהמפתח פסול** — הדרך היחידה לדעת היא לנסות אותו: בעורך
   ה-Apps Script בחרו את הפונקציה `testGeminiKey` והריצו. היומן יראה אם
   המפתח עובד, או את הודעת השגיאה המדויקת של גוגל.

**הזנת המפתח ב-Apps Script:**
1. בעורך ה-Apps Script, בתפריט הצדדי: **⚙️ Project Settings**.
2. גללו לקטע **Script Properties** ← **Add script property**.
3. **Property**: `GEMINI_API_KEY` (בדיוק כך — אותיות גדולות וקו תחתון).
4. **Value**: הדביקו את המפתח.
5. **Save script properties**.

אם השם לא מדויק, השיחה תיכשל עם ההודעה:
`לא הוגדר GEMINI_API_KEY ב-Script Properties`.

> **אבטחה:** אם מפתח נחשף אי פעם (נשלח בצ'אט, הועלה ל-git, שותף בצילום מסך) —
> יש לבטל אותו ב-AI Studio וליצור חדש. מפתח חשוף מאפשר לכל אחד לחייב את
> החשבון שלכם.

## מבנה הקורס

הקורס בנוי כ**שדרה אחת של שיטה, שרצה על מודולים מתחלפים של מאגרים**. התלמידים
אינם "בונים מודל" - הם מריצים ניסויים מבוקרים ובודקים מה באמת משפיע על התוצאה.

**ארבעת הניסויים.** כל תלמיד/ה מריץ/ה את כולם - זו הסיבה שאין "אסטרטגיה אישית":

| ניסוי | השאלה | המלכודת |
|---|---|---|
| עקומת למידה | כמה תמונות באמת צריך, ואיפה העקומה מתיישרת | ערכות לא מקוננות מודדות בחירה במקום כמות |
| יחסי איזון | מה קורה כשמחלקה אחת נדירה | הדיוק הכולל מסתיר קריסה של הרגישות |
| הכללה בין מקורות | האם המודל למד את הממצא או את המקור | ציון גבוה על אותו מקור אינו עדות ליכולת |
| התערבות | האם התיקון עובד, ומה מחירו | שינוי של שני דברים יחד |

**המודולים.** מלריה פותחת (קלה, ניתנת לאימות בעין, מתרגלת את הצנרת), צילומי חזה
אחריה (קשה יותר, כשלים אמיתיים). MURA וכל השאר נשמרים כרזרבה - נשלפים אם החומר
נשרף מהר מדי. המורה קובע/ת את המאגר הפעיל בעת פתיחת שבוע חדש; ברירת המחדל היא
המאגר של השבוע הקודם, כי מעבר מודול הוא אירוע מכוון ולא בחירה שבועית.

**הקצב.** המאגר קבוצתי (חלוקת ערכות האימון פיזית ממילא), אך כל תלמיד/ה מסמן/ת
בעצמו/ה באיזה ניסוי הוא/היא נמצא/ת, ומתקדם/ת בקצב שלו/ה. המנטור מקבל את שני
הערכים ושואל על הניסוי המסומן.

**כלי הבדיקה** שמלווים כל ניסוי נמצאים תחת `tools/`: הערכת מודל (מדדים, מפת
קשב), כלי הפרעות (מה באמת מניע את ההחלטה) ומחברת ניסוי (השערה שננעלת לפני
המדידה, תנאים, מדידה, מסקנה). כל ייצוא מהם מתויק אוטומטית בתיקיית התלמיד/ה
ב-Drive, בתנאי שהכלי נפתח מתוך המערכת.

### עדכון פריסה קיימת
כל שינוי בקוד ה-`Code.gs` דורש **Manage deployments ← Edit ← New version** כדי
שהשינויים ייכנסו לתוקף (Apps Script לא מעדכן פריסות קיימות אוטומטית).

> **העורך והפריסה הם שני עותקים נפרדים.** פונקציה שמורצת מהעורך רצה על הקוד
> שנשמר; המערכת רצה על הקוד שנפרס. לכן ייתכן מצב שבו `testGeminiKey` בעורך
> מדווחת שהכל תקין, ובאותו רגע המערכת מציגה שגיאה ישנה — פשוט מפני שהגרסה
> שנפרסה קדמה לתיקון.

**איך לוודא שהפריסה באמת התעדכנה** — שולחים לכתובת ה-`/exec` בקשה לפעולה
שקיימת רק בקוד החדש, ולצדה בקשה לפעולה מומצאת:

```js
fetch(API_URL, {method:'POST', headers:{'Content-Type':'text/plain;charset=utf-8'},
  body: JSON.stringify({action:'saveArtifact', payload:{}})}).then(r=>r.json()).then(console.log);
```

| התשובה | המשמעות |
|---|---|
| `פג תוקף ההתחברות` | הפעולה קיימת ומוגנת — הפריסה מעודכנת |
| `פעולה לא מוכרת` | הפריסה עדיין מגישה קוד ישן |

התשובה זהה לזו של פעולה שלא קיימת כלל, ולכן הבקשה המומצאת היא הבקרה שמבדילה
בין "לא נפרס" ל"נכשל מסיבה אחרת".

**אם `New version` לא תופס** (קרה בפועל): צרו **פריסה חדשה** לגמרי, והחליפו את
`API_URL` ב-`js/config.js` בכתובת שהתקבלה. הפריסה הישנה תמשיך להתקיים ולהגיש
קוד ישן — ודאו שאף אחד לא מפנה אליה.

### תחילת שנה — הגדרת שבוע ראשון וייבוא תלמידים
1. בפאנל הניהול, הזינו "נושא השיעור השבועי" ולחצו **שבוע חדש** כדי לפתוח את שבוע 1.
2. הכינו קובץ Excel עם העמודות: שם פרטי, שם משפחה, תעודת זהות מלאה, תאריך
   לידה, קבוצה. עמודת "הערה" אופציונלית. קובץ תבנית: `תבנית_רשימת_תלמידים.xlsx`.
3. העלו את הקובץ בפאנל הניהול ← "ייבוא תלמידים מקובץ Excel" ← נתחו ← ייבוא.
   הקובץ נקרא ומעובד **בדפדפן בלבד** (SheetJS) — תעודת הזהות המלאה לעולם לא
   נשלחת לשרת, רק 4 הספרות האחרונות (לצורך שם המשתמש).

## אבטחה ופרטיות - הערות חשובות

- **אימות מבוסס טוקן**: פריסת ה-Web App פתוחה ל-`Anyone` (נדרש כדי שהאפליקציה
  תוכל לפנות לשרת ללא התחברות Google), ולכן כתובת ה-`/exec` היא נקודת קצה
  ציבורית. כדי שזה לא יחשוף את נתוני התלמידים, **כל פעולה חוץ מההתחברות דורשת
  טוקן תקף**: התחברות מוצלחת מייצרת טוקן בגיליון `Sessions` (תוקף 24 שעות),
  והוא נשלח בכל בקשה. תלמיד/ה יכול/ה לגשת רק לנתונים של עצמו/ה; פעולות ניהול
  (דשבורד, ייבוא, ייצוא, דריסת ציון) מוגבלות לתפקיד `admin`.
- הסיסמאות נשמרות כגיבוב SHA-256 בלבד. **אין חיוב להחליף סיסמה** — כל תלמיד/ה
  נשאר/ת עם הסיסמה שנגזרה מתאריך הלידה, והמורה עם סיסמת ברירת המחדל.
  המשמעות: פרטי ההתחברות ניתנים לניחוש ממידע שאינו סודי בבית ספר (שם פרטי,
  4 ספרות אחרונות של ת"ז, תאריך לידה). מקובל לכלי כיתתי, אך יש לזכור שתמלולים
  וציונים של תלמיד/ה נגישים למי שמנחש את פרטיו/ה.
  המורה יכול/ה לאפס סיסמה לתלמיד/ה בכל רגע דרך כפתור 🔑 בדשבורד.
- תעודת זהות מלאה **אינה נשמרת בשום שלב** — נקראת ומעובדת בדפדפן המורה בלבד
  בזמן ייבוא האקסל, ורק 4 הספרות האחרונות (לצורך שם המשתמש) מגיעות לשרת.
- זהו פתרון אימות פשוט המתאים לכלי כיתתי פנימי — אין בו rate limiting, ואין
  הגנה מפני ניחוש סיסמאות חוזר. לא מיועד לאחסון מידע רפואי אמיתי של מטופלים: יש
  להשתמש רק בתמונות ממאגרים ציבוריים מאושרים (NIH/Kaggle וכד', anonymized).
- תמונות התלמידים נשמרות ב-Drive של המורה (לא בגיליון עצמו), ביומני Docs
  אישיים לכל תלמיד/ה.
- **התמונות מוקטנות אוטומטית בדפדפן** לפני השליחה (עד 1024px, JPEG) — חוסך
  עלות טוקנים ב-Gemini, זמן המתנה ונפח ב-Drive. בבדיקה, צילום של 5MB ירד
  ל-153KB. תמונות שכבר קטנות (מתחת ל-1024px ו-300KB) עוברות ללא שינוי.
  הפרמטרים נמצאים בראש `js/studentChat.js`.

### החלפת סיסמת המורה

> ⚠️ **החליפו אותה לפני שתלמידים נכנסים למערכת.** ברירת המחדל `admin123`
> מתועדת כאן, וה-README הזה נמצא במאגר ציבורי — כלומר כל עוד היא בתוקף,
> מי שמוצא את כתובת האתר יכול להיכנס כמורה, לקרוא תמלולים ולשנות ציונים.

**הדרך הרגילה:** בפאנל הניהול, בכרטיס **🔒 סיסמת המורה** — הזינו סיסמה חדשה
פעמיים ולחצו. נדרשים 8 תווים לפחות, והשינוי נכנס לתוקף מיד.

**אם נשכחה הסיסמה** ואי אפשר להיכנס לפאנל, עורכים ישירות את גיליון `Users`:

1. חשבו את גיבוב ה-SHA-256 של הסיסמה הרצויה — למשל דרך
   [emn178.github.io/online-tools/sha256.html](https://emn178.github.io/online-tools/sha256.html).
2. בגיליון `Users`, בשורת ה-`admin`, הדביקו את הגיבוב בעמודה **`passHash`**.
3. השינוי נכנס לתוקף מיד.

לשם השוואה, הגיבוב של `admin123` (ברירת המחדל) הוא:
`240be518fabd2724ddb6f04eeb1da5967448d7e831c08c8fa822809f74c720a9`

**איפוס מלא:** מחיקת הלשוניות `Users` ו-`Sessions` תיצור אותן מחדש בכניסה
הבאה, עם משתמש `admin`/`admin123` נקי. שימו לב שזה מוחק גם את כל התלמידים
שיובאו (הצ'ק-אינים והציונים נשמרים בגיליונות נפרדים).

### החלפת מודל Gemini (כשמודל יוצא משימוש)

גוגל מוציאה משימוש מודלים ישנים מדי פעם, ואז מופיעה שגיאה בסגנון
`This model ... is no longer available to new users`. אין צורך לערוך קוד:

1. בעורך ה-Apps Script בחרו בתפריט הפונקציות את **`listAvailableModels`**
   ולחצו ▶ **Run**.
2. פתחו את **Execution log** — תופיע רשימת כל המודלים שהמפתח שלכם יכול להריץ.
3. בחרו מודל מהרשימה (עדיפות ל-Flash-Lite הזול ביותר שקיים בה).
4. **Project Settings ← Script Properties** ← הוסיפו מאפיין:
   - **Property**: `GEMINI_MODEL`
   - **Value**: שם המודל מהרשימה (למשל `gemini-3.1-flash-lite`)
5. שמרו. השינוי נכנס לתוקף מיד — **אין צורך בפריסה מחדש**, כי הערך נקרא
   בזמן ריצה.

ברירת המחדל בקוד היא `DEFAULT_GEMINI_MODEL` בראש `Code.gs`, ומשמשת רק אם
המאפיין `GEMINI_MODEL` לא הוגדר.

### מגבלות שימוש (הגנה תקציבית)

הצ'אט פתוח לשיחה חופשית, ולכן תלמיד/ה יכול/ה לנסות להשתמש בו למשימות שאינן
קשורות לפרויקט. הנחיה בפרומפט **אינה** הגנה תקציבית — אפשר לשכנע את המודל
לחרוג ממנה, וגם סירוב עולה כסף. לכן המגבלות נאכפות בשרת, ב-`Code.gs`:

| קבוע | ברירת מחדל | מה הוא חוסם |
|---|---|---|
| `WEEKLY_MESSAGE_QUOTA` | 80 הודעות לשבוע | שימוש מופרז, ידני או אוטומטי |
| `GRADED_RESERVE` | 10 | רזרבה שמבטיחה שאפשר תמיד להשלים את החלק המוערך גם אחרי מיצוי המכסה |
| `MIN_SECONDS_BETWEEN_MESSAGES` | 3 שניות | סקריפטים ששולחים בקשות בלולאה |
| `MAX_HISTORY_TURNS` | 16 תורות | תפיחת עלות בשיחות ארוכות (ההיסטוריה נשלחת מחדש בכל קריאה) |
| `MAX_MESSAGE_CHARS` | 4000 | הדבקת קבצי קוד/טקסט ענקיים |

הספירה נשמרת בגיליון `Usage` ומתאפסת בכל שבוע חדש. העדכון עטוף ב-`LockService`
כדי שלא ניתן יהיה לעקוף את המונה בשליחת בקשות מקבילות.

**רשת ביטחון אחרונה:** הגדירו Budget/Alert בפרויקט ה-Google Cloud המשויך.
זה הדבר היחיד שמבטיח תקרת הוצאה אמיתית, ללא תלות בקוד.

## עלות Gemini API

מומלץ לבחור תמיד את מודל ה-**Flash-Lite** הזול ביותר שזמין לכם (ראו
"החלפת מודל Gemini" למעלה) — הוא מספיק בהחלט למשימה הזו.

הערכת עלות: גם בשימוש כבד (60 תלמידים, כולל צ'אט עזרה בלתי מוגבל) מדובר
בכמה דולרים בודדים לחודש. שימו לב שמודלים חדשים יקרים ממודלים ישנים — בעת
החלפת מודל שיצא משימוש, בדקו את התמחור המעודכן ב-
[ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing).

מומלץ להגדיר Billing Alert בפרויקט ה-Google Cloud המשויך על סף התקציב שלכם.

## הרחבת שכבת ה-API

| פונקציה | תיאור |
|---|---|
| `authenticateUser(user, pass)` | אימות התחברות — מחזיר טוקן (הפעולה היחידה שאינה דורשת טוקן) |
| `logout()` | ביטול הטוקן בשרת |

| `resetStudentPassword(studentId, newPassword)` | איפוס סיסמה ע"י המורה |
